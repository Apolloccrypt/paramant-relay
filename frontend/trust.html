TRANSPARANTIE

Vertrouwen en controle

Voor organisaties die Paramant op hun eigen server draaien, en voor iedereen die een leverancier moet controleren voordat die bij klantdocumenten komt, staat hier wat wij kunnen zien, wat wij kunnen doen en hoe je dat zelf nagaat. Je hoeft ons dus niet op ons woord te geloven. Gebruik je de gehoste dienst op paramant.app, dan is de beveiligingspagina het kortere antwoord.

Bekijk het bewijs → Bekijk de prijzen →

Voor wie deze pagina is

Alles hieronder is geschreven voor twee lezers: de beheerder van de server waar de bestanden doorheen gaan, en degene die die server moet goedkeuren. Je leest wat Paramant wel en niet kan op een server die niet van Paramant is.

Iedereen kan Paramant gratis gebruiken. Ondertekenen Community en Versturen Community kosten €0, zonder einddatum, en je hoeft geen betaalkaart op te geven. Organisaties betalen voor hogere limieten. Daarvoor zijn er Firm, Ondertekenen Business en Enterprise, en Versturen Enterprise. Met Firm betaal je één keer voor beide producten. Bij Ondertekenen Enterprise en Versturen Enterprise betaal je voor een eigen server, een SLA (afspraken over beschikbaarheid) en een licentie om Paramant zelf te draaien. Elk abonnement krijgt dezelfde versleuteling, dezelfde handtekeningen die bestand zijn tegen quantumcomputers en hetzelfde openbare logboek als bewijs. Bekijk de prijzen →

Zo lees je deze pagina

Paramant was tot nu toe één programma dat je zelf op een server installeert. Het wordt een open-core product. De serversoftware blijft openbaar en draait volledig op je eigen server. Daarnaast beheert Paramant een centrale dienst voor licenties en beheer. Een deel van die overgang werkt al, een deel staat nog alleen op papier.

Daarom is elke bewering hieronder gemarkeerd. Live betekent dat het vandaag werkt op de openbare server. Gepland betekent dat het is beschreven in een openbaar ontwerpdocument (een ADR) en nog niet is gebouwd. Zo lees je nergens dat iets bestaat voordat het er is.

Zo werkt de licentiecontrole

Nu Live werkt de server met een offline licentie. Je PLK_KEY is een licentiecode die Paramant digitaal heeft ondertekend (met Ed25519). De server controleert die handtekening zelf, met een publieke sleutel die in de software is ingebouwd. In de licentiecode staan het maximum aantal gebruikers, de vervaldatum en aan wie de licentie is uitgegeven. Om de licentie te controleren neemt de server geen contact met ons op. Zonder licentiecode, of met een verlopen code, draait de server gewoon als Community Edition (5 gebruikers). Voor de licentiecontrole gaat er niets van je server naar buiten.

Gepland Gepland is een online licentiecontrole. Die is nodig om abonnementen te verkopen die meer regelen dan een aantal gebruikers. In dat ontwerp meldt je server zich bij het opstarten en daarna elke 6 uur bij een licentieadres van Paramant. Hij stuurt dan mee: je licentiesleutel, de identiteit van je server, het versienummer van de software en een blok gebruiksgegevens (telemetrie) dat standaard uit staat. Die identiteit is de vingerafdruk van een publieke sleutel die je server bij de eerste start zelf aanmaakt. Die sleutel werkt met ML-DSA-65, een handtekeningmethode die bestand is tegen quantumcomputers.

Paramant antwoordt met een ondertekende lijst van functies: wat je abonnement vrijgeeft. Die lijst is een paar uur geldig. Je server controleert de ML-DSA-65-handtekening met een licentiesleutel van Paramant die in de software is ingebouwd. Een antwoord zonder handtekening, of met een ongeldige, wordt geweigerd. Is het licentieadres niet bereikbaar, dan gebruikt de server tot 7 dagen de laatst bewaarde lijst. Daarna valt hij terug op de Community-modus. Een storing bij ons kan je server dus niet meteen uitschakelen, en je wordt niet onverwacht buitengesloten.

De volledige beschrijving van dit protocol staat in ADR R013 (concept), in de openbare ADR-map.

Wat Paramant van je server ziet

Met de huidige offline licentie is het antwoord eenvoudig: niets, zolang de server draait. De server vraagt over de licentie niets bij ons op. Het overzicht hieronder beschrijft het online model dat Gepland is, zodat je het kunt beoordelen voordat het er is.

Altijd (bij elke melding van je server)

  • Je licentiesleutel: zo herkennen wij je abonnement
  • De vingerafdruk van je server (een hash van zijn publieke ML-DSA-65-sleutel)
  • Het versienummer van de software op je server
  • Het tijdstip van de melding

Alleen als je daarvoor kiest (gebruiksgegevens, standaard uit)

  • Totaal aantal gebruikers: een getal, nooit identiteiten
  • Totaal aantal verzendingen per 24 uur: een getal, nooit hashes
  • Foutpercentages (het aandeel serverfouten en het aandeel mislukte aanmeldingen)
  • Uptime

Nooit, ook niet als gebruiksgegevens aan staan

  • De inhoud van bestanden: je sleutels liggen nergens bij ons
  • Identiteiten van je gebruikers (e-mailadressen, namen)
  • Hashes van bestanden: daarmee zouden afzonderlijke verzendingen te herleiden zijn
  • Afzender- of bestemmingsadressen van je verzendingen
  • De inhoud van het openbare logboek (de CT-log), behalve totalen

Gepland Voordat je gebruiksgegevens kunt aanzetten, toont het beheerpaneel precies wat je server dan zou versturen, zonder verborgen velden. Zo weet je wat je aanzet.

Zo controleer je je eigen installatie

Je hoeft deze uitspraken niet te geloven. Je kunt ze controleren met wat openbaar is.

1. Broncode Live

De broncode van alles wat op je server draait staat openbaar op GitHub, onder de licentie BUSL-1.1. Dat zijn de serversoftware, het beheerpaneel, de SDK's (bouwstenen voor ontwikkelaars) en de licentie-client, het deel dat de licentiecontrole uitvoert. Je kunt precies lezen wat je server doet, ook elk veld dat hij zou versturen. Je kunt de software ook zelf bouwen:

git clone https://github.com/Apolloccrypt/paramant-relay
cd paramant-relay
git checkout v3.0.0
docker compose build   # build locally instead of pulling the published image

2. Het kant-en-klare image Live

Het kant-en-klare image op Docker Hub (een pakket waarin de software klaar staat om te draaien) wordt uit dezelfde broncode gebouwd, met een openbare GitHub Actions-workflow. Je kunt een image dat je zelf bouwt vergelijken met de versie op Docker Hub. Je kunt Docker Hub ook overslaan en alleen de versie draaien die je zelf hebt gebouwd.

Op /partners staat van welke externe partijen de dienst afhangt en wat elk daarvan krijgt.

3. Ondertekende releases Gepland

In het ontwerp krijgt elke nieuwe versie een digitale handtekening, zodat je de herkomst kunt controleren zonder zelf te bouwen. Dat bestaat nog niet. Zodra het werkt, ziet de controle er zo uit:

cosign verify mtty001/relay:3.0.0 \
  --key https://paramant.app/.well-known/paramant-release.pub

Het ondertekenen van nieuwe versies en de betrouwbaarheid van de hele bouwketen staan in het ontwerpdocument over het releaseproces (ADR R015, nog in bewerking), in de openbare ADR-map.

4. Gedrag Live

Elke verzending die via je server loopt, komt in een openbaar logboek van die server: de Certificate Transparency-log. Dat logboek is een ondertekende Merkle-boom, een opbouw waarin een latere wijziging opvalt. Je kunt het zelf inzien en bewaren. Daarnaast houdt de server in zijn eigen logbestanden bij welke verbindingen hij naar buiten maakt. Zodra de online licentiecontrole er is, wordt ook elke melding bij ons vastgelegd, zodat je kunt zien wat je server verstuurt.

Wat Paramant op afstand kan doen

Wat hieronder staat over acties op afstand is Gepland: het is beschreven en nog niet gebouwd. De grenzen onder "Niet mogelijk" gelden wel al Live. Die volgen uit de manier waarop de software is gebouwd, en hangen niet af van een afspraak of beleid.

In het ontwerp komt elke actie op afstand in het openbare logboek van je eigen server, waar je die zelf kunt controleren. Je ziet wat er is gedaan, wanneer, en vanuit welke rol bij Paramant (Owner of Support). Welke medewerker het deed, leggen wij daarnaast vast in ons eigen interne logboek. Dat deel blijft intern.

Mogelijke acties op afstand (gepland)

Een tijdelijke supportsleutel uitgeven
Een sleutel die na een vaste tijd verloopt, om een probleem te onderzoeken dat je hebt gemeld. Je kunt hem in je beheerpaneel direct intrekken.
Een update aanbieden
Een nieuwe versie klaarzetten voor je server. Hoe die wordt geïnstalleerd, hangt af van je abonnement. Je krijgt een melding en beslist zelf, de update komt in een tijdvak dat je hebt gekozen, of er is eerst je uitdrukkelijke goedkeuring nodig. Er komt nooit ongemerkt een update binnen waar je niet mee hebt ingestemd.
De server laten afbouwen
De server vragen geen nieuwe bestanden meer aan te nemen, lopende verzendingen af te maken en daarna te stoppen. Dit is bedoeld voor onderhoud.
Je vrijgegeven functies aanpassen
Een wijziging in je abonnement doorvoeren, zoals een verlengde proefperiode of een upgrade na betaling. Die gaat in bij de volgende melding van je server.

Niet mogelijk, door hoe de software is gebouwd Live

  • Je bestanden lezen. Wij hebben geen sleutels om ze te ontsleutelen. De uitzondering is het ondertekenen via onze gehoste dienst op /v1. Bij versturen op naam ziet onze server de link één keer, maar zonder de code die de afzender zelf doorgeeft, gaat het bestand niet open.
  • Je logboek herschrijven zonder dat het opvalt. Een herschreven logboek spreekt elke eerder ondertekende momentopname (tree head) tegen, en elk ontvangstbewijs bevat zo'n momentopname.
  • De tweestapscodes (TOTP) of de beheersleutel van je eigen server omzeilen. Er zit geen achterdeur in de broncode, en die broncode is openbaar.
  • Bij de gegevens van je gebruikers komen, of bij die van een andere installatie. Installaties staan bewust los van elkaar.
  • Je logboek uitzetten. Het bijschrijven in het logboek hangt niet af van de functies die wij vrijgeven.

Het protocol voor acties op afstand staat in het ontwerpdocument over de beheerdienst (ADR R014, nog in bewerking), in de openbare ADR-map.

Open-core: wat openbaar is en wat niet

Paramant werkt volgens het open-core model, net als HashiCorp, GitLab, Elastic en Sentry. De software die je zelf draait is openbaar. De dienst waarmee wij die software beheren, is dat niet.

Openbaar op GitHub, onder BUSL-1.1 Live

  • De serversoftware: alles wat op je server draait
  • De SDK's en de opdrachtregelprogramma's (CLI)
  • De webschermen: het beheerpaneel, de installatiewizard en het dashboard
  • De licentie-client: de code op je server die zich bij ons meldt
  • Alle ontwerpdocumenten (ADR's), ook die over licenties en de beheerdienst
  • De beschrijving van de versleuteling, met testvectoren om die na te rekenen

Bekijk de broncode op GitHub →

Niet openbaar: intern beheerd door Paramant

  • De licentie-server: onze kant van de licentiecontrole
  • Het interne dashboard waarmee wij alle servers beheren
  • De databases voor klanten en facturatie
  • Supporttools en e-mailsjablonen

De protocollen zijn openbaar. Alleen de software aan onze kant houden wij intern, zoals GitLab zijn bedrijfsvoering intern houdt en de software zelf openbaar laat. Omdat het protocol en de code aan je kant openbaar zijn, kun je precies nagaan wat je server naar ons stuurt en welke antwoorden hij accepteert.

Deze verdeling staat in het ontwerpdocument over open-core (ADR R016), in de openbare ADR-map.

Onafhankelijke controle

In april 2026 hebben drie externe beveiligingsaudits de code van de serversoftware beoordeeld: twee door R. Zwarts, één door Ryan Williams van Smart Cyber Solutions. Samen leverden ze 40 bevindingen op, waarvan 4 kritiek. De datums, de aantallen bevindingen en de codewijzigingen waarmee ze zijn opgelost, staan in de audittabel op de docs-pagina. Elke bevinding is beschreven in SECURITY.md. Het volledige rapport van Smart Cyber Solutions staat online als het auditrapport van april 2026. De ruwe uitvoer van de inbraaktests daarachter is niet openbaar. Een volgende externe beoordeling, van versie 3.0.0 en de open-core opzet, is gepland. De uitkomsten komen op dezelfde plek te staan zodra ze klaar zijn.

Doe je zelf een audit, dan heb je genoeg aan wat openbaar is: de serversoftware, de SDK's, de webschermen en de beschrijving van de protocollen. Daarmee kun je elke bewering op deze pagina controleren.
