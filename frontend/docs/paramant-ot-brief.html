PARAMANT

Ghost Pipe: industriële OT-brief

ML-KEM-768 IEC 62443 Burn-on-read Zelf gehost ARM64

Gegevens veilig van OT naar IT brengen is lastig door de manier waarop de netwerken zijn opgebouwd.

OT-netwerken kunnen niet rechtstreeks met cloudsystemen verbinden. VPN’s zorgen voor een blijvend aanvalsoppervlak. Oudere protocollen (FTP, SMB, OPC-DA) zijn niet bestand tegen quantumcomputers. Sensordata die onderweg is, wordt nu al verzameld om later te ontsleutelen. Die dreiging heet Harvest Now, Decrypt Later (HNDL). Ghost Pipe, het overdrachtsprotocol van Paramant, is een quantumveilig datakanaal dat is ontworpen voor de zonegrens van IEC 62443.

Oplossing

Wat de server is

De server is een doorgeefluik op de zonegrens in je DMZ. Hij werkt alleen in het werkgeheugen (RAM) en slaat niets blijvend op. Je hebt geen VPN nodig en hoeft je netwerk niet aan te passen. Sensordata komt versleuteld binnen en wordt na aflevering vernietigd.

Je plaatst hem op een Raspberry Pi 3B+ op veldniveau, of op een Linux-server in je bestaande DMZ.

Wat het niet is

De server is geen SCADA-historian en vervangt geen VPN voor algemeen verkeer. Het is ook geen clouddienst waar je van afhankelijk wordt: de server draait in je eigen infrastructuur, met je eigen sleutels, en werkt zo nodig zonder externe verbinding.

Belangrijkste eigenschappen

  • ML-KEM-768 (NIST FIPS 203): post-quantum sleuteluitwisseling, bestand tegen harvest-now-decrypt-later
  • ML-DSA-65 (NIST FIPS 204): post-quantum apparaathandtekeningen bij elke overdracht
  • Server alleen in RAM: er staat niets blijvend opgeslagen dat een inbreker of een forensisch onderzoek kan kopiëren
  • IEC 62443 SR 4.1, 4.2, 3.1, 2.8, 5.2: de compliancedocumentatie wordt meegeleverd en bijgehouden
  • Native ARM64: draait op een Raspberry Pi 3B+ op veldniveau (minimaal 512 MB RAM)
  • Zelf gehoste server in je DMZ: je bent niet afhankelijk van een externe dienst en heeft geen SaaS-contract nodig
  • Rechtsgebied EU/DE: de beheerde server draait bij Hetzner in Duitsland en valt niet onder de Amerikaanse CLOUD Act. Alle partijen met hun status: /partners
  • Broncode openbaar onder BUSL-1.1: je kunt elke regel controleren op github.com/Apolloccrypt/paramant-relay
  • CT-auditlog: een log op basis van Merkle-bomen. Knoeien wordt zichtbaar en elke overdracht is cryptografisch aantoonbaar

Architectuur en installatie

Purdue Model Ghost Pipe v2 april 2026

Plaats in het Purdue-model

Level 4 Enterprise IT ← Cloud SCADA / historian / ERP Level 3 Operations IT ← paramant-receiver (Linux daemon or Python) ───────────────────────────────────────────────────────────────── Level 3.5 DMZ (conduit) ← Ghost Pipe relay (self-hosted, your server) ───────────────────────────────────────────────────────────────── Level 2 Control ← paramant-sender (PLC gateway / HMI) Level 1 Field devices PLC / DCS / sensor output → gateway Level 0 Physical process

Gegevensstroom

PLC output → paramant-sender (Level 2) → [ML-KEM-768 encrypt client-side] → Ghost Pipe relay (DMZ): stores ciphertext in RAM only, TTL 10 min default → [burn-on-read] → paramant-receiver (Level 3) → [client-side decrypt] → SCADA historian / cloud

Bij versturen met Ghost Pipe en de SDK, zoals in deze brief, bewaart de server alleen versleutelde data, alleen in RAM, en alleen tot de aflevering. Hij weet niets van sensorwaarden, apparaat-ID’s of processtatus. Ook als de server volledig wordt gekraakt, levert dat geen enkele leesbare data op.

Eigenschappen van de server

  • Ontvangt alleen versleutelde data: ziet nooit leesbare sensorwaarden
  • Opslag alleen in RAM: gewist na aflevering of na afloop van de TTL
  • Signed Tree Head, ondertekend met ML-DSA-65, na elke Merkle-update
  • Inclusion proof per overdracht: iedereen kan knoeien opsporen
  • Register van apparaatidentiteiten: /v2/did/register
  • WebSocket-streaming: lage vertraging voor doorlopende sensordata
  • Koppeling met NATS.io: optioneel push-transport
  • API-sleutels per apparaat: je kunt ze intrekken
  • Geschikt voor air-gap: zelf gehost heeft de server geen internetverbinding nodig
  • Docker Compose: één keer docker compose up

Voorbeelden van koppelingen

Doorlopende sensormodus

paramant-sender \ --interval 15 \ --device-id plc-line-01 \ --key pgp_xxx \ sensor-output.json

Verstuurt elke 15 seconden één versleuteld pakket. Elk pakket wordt vernietigd zodra de ontvanger het leest. Interval en TTL zijn in te stellen.

Firmware verspreiden

paramant-firmware \ --sign firmware-v2.1.bin \ --device-group factory-01 \ --key pgp_xxx \ --ttl 86400

Ondertekent het firmwarebestand met ML-DSA-65 en verspreidt het naar een apparaatgroep. Elk apparaat downloadt één keer en daarna wordt het pakket vernietigd.

Installatie aan de rand (Raspberry Pi)

curl -fsSL https://paramant.app/install-pi.sh | bash # → Installs relay on ARM64, configures systemd service, generates relay identity

Minimale hardware: Raspberry Pi 3B+ · 512 MB RAM · 4 GB SD · Ethernet. Een scherm is niet nodig. Je sluit het apparaat aan op het netwerksegment van je DMZ.

Compliancematrix IEC 62443

IEC 62443-3-3 SL-T 2 standaard SL-T 3 zelf gehost

De tabel hieronder koppelt de System Security Requirements van IEC 62443-3-3 aan eigenschappen van het Ghost Pipe-protocol. Documentatie staat op paramant.app/docs#compliance-iec62443.

Eis Titel Uitwerking in Ghost Pipe SL-T
SR 4.1 Vertrouwelijkheid van informatie Versleuteling met ML-KEM-768 bij de client. Bij versturen met de SDK en Ghost Pipe, zoals in deze brief, krijgt de server nooit leesbare data. De blobs worden opgevuld tot een vaste grootte, zodat verkeersanalyse niets ziet en de grootte van SCADA-berichten niet uitlekt. 2–3
SR 4.2 Gebruikscontrole API-sleutel per apparaat (pgp_ eindgebruiker, plk_ beheerder). Registratie van apparaatidentiteit via /v2/did/register. Je kunt sleutels intrekken. Per sleutel is er een audittrail. 2–3
SR 3.1 Integriteit van communicatie Signed Tree Head met ML-DSA-65 (NIST FIPS 204) na elke update van de Merkle-root. Inclusion proof per overdracht: iedereen kan knoeien opsporen, ook onafhankelijke auditors. 2–3
SR 2.8 Controleerbare gebeurtenissen Openbare Certificate Transparency-log op paramant.app/ct. Er kan alleen iets aan worden toegevoegd. Knoeien valt op, en iedereen kan de log controleren. Export naar SIEM wordt ondersteund (JSON + CSV). De hash van elke overdracht wordt gelogd. 2–3
SR 5.2 Bescherming van de zonegrens Zelf gehoste server in de DMZ. Er gaat geen blijvend opgeslagen data over de zonegrenzen. Een directe verbinding tussen L2 en L3 is niet nodig. In air-gapmodus werkt de server zonder extern internet. 2–3
SR 1.1 Identificatie van menselijke gebruikers Aanmelden van apparaten via POST /v2/did/register met een publieke ECDH-sleutel. Een DID (Decentralized Identifier) per apparaat. Je kunt sleutels vervangen en intrekken. 2
SR 1.2 Identiteit van softwareprocessen Apparaatidentiteit gekoppeld aan een publieke ML-DSA-65-sleutel. Elke overdracht is ondertekend door het apparaat van herkomst. De server kan de identiteit niet vervalsen. 2
SR 2.1 Handhaving van autorisatie Quotum en snelheidslimiet per sleutel. Toegang op basis van abonnement (free / pro / enterprise). De server weigert sleutels boven de limiet van het abonnement met HTTP 402/429. 2

Security Level Target

  • SL-T 2: standaardinstelling van de beheerde server
  • SL-T 3: zelf gehoste server, air-gapped, geen extern internet
  • Voor SL-T 3 zijn nodig: een zelf gehoste server, een eigen sector en geen afhankelijkheid van externe DNS

Let op: de compliancedocumentatie koppelt wat Ghost Pipe kan aan de eisen van IEC 62443. Het is geen certificering door een derde partij. Klanten die SL-T 3-certificering willen, schakelen voor formele toetsing een gecertificeerde IACS-keuringsinstantie in (bijvoorbeeld TÜV of DNV).

Beheerde server

iot.paramant.app, Hetzner DE. Gratis evaluatie: 1000 overdrachten per 30 dagen, geen daglimiet. Sleutels voor Pro en Enterprise zijn beschikbaar.

docker compose up -d # or curl -fsSL paramant.app/install.sh | bash

Werkt op elke Linux-server. Een systemd-unit en een reverse-proxyconfiguratie voor nginx of Caddy worden meegeleverd.

curl -fsSL \ paramant.app/install-pi.sh \ | bash

Draait native op ARM64 met minimaal 512 MB RAM, zonder scherm. Geschikt voor een DMZ-segment op veldniveau.
